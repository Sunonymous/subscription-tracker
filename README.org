* Project Overview
This is an extremely simple subscription viewer and manager. You may enter data describing your personal financial subscriptions and view them all in one place. All data stays local and may be imported/exported to other devices at will. This tool should also work to provide a concrete record for your regular recurring expenses if the need of sharing it arises.

* UI Implementation Plan
The interface is being built incrementally, card-by-card, rather than all at
once. Each phase below is checked off once it actually lands in the code
sections further down, so this list stays a true reflection of what exists,
not just what was intended.

- [X] Phase 0 --- Retro documentation pass: short Org prose next to every existing code block explaining the /why/, not just the code.
- [X] Phase A --- Read-only subscription list: render
  =::subs/subscription-list= as abbreviated cards. Validates the data flow end-to-end before any interactivity is added.
- [X] Phase B --- Expand/collapse per card (local component state), showing full field detail.
- [ ] Phase C --- Edit-in-place: an "Edit" toggle in the expanded card swaps to the same form used for creation, dispatching =::events/update-subscription=.
- [X] Phase D --- Create: an inline "+ Add subscription" form at the top of the list, dispatching =::events/add-subscription=. (Built ahead of Phase C: with no data at all, there was nothing to verify Phase B against, and this form is what Phase C will reuse for editing anyway.)
- [ ] Phase E --- Delete: a control plus confirm step, dispatching =::events/remove-subscription=.
- [ ] Phase F --- Accounts: mirror B--E for accounts, including delete confirmation copy that reflects the =::events/remove-account= unlink-cascade.
- [ ] Phase G --- Category autocomplete and color assignment: a derived sub over =::db/categories= keys feeding a =<datalist>= on the subscription form, plus a way to set/change a category's =:color=.
- [ ] Phase H --- Derived stats bar: a =subscription-tracker.util= namespace for cost normalization, plus a sub for total monthly/yearly spend and active count.
- [ ] Phase I --- Filtering & sorting: a =:ui= app-db slice (sort key/direction, filters) plus controls; cancelled subscriptions sorted to the bottom and visually dimmed by default.
- [ ] Phase J --- Import/export: download =:subscriptions=/=:accounts= as a file; re-validate through =::db/db= spec before merging an import back in.

** NS: subscription-tracker.db
File path: =src/subscription_tracker/db.cljs=

The two =default-*= maps are shapes/templates, not valid instances --- most
fields are =nil= placeholders meant to be =merge=d over when creating a real
entity (see =::events/add-subscription=/=::events/add-account=), not values
that satisfy the spec below on their own.

=:billing-day= is a plain integer, 1--31, rather than a full anchor date.
An earlier version stored a full ISO date so the next charge could in
principle be derived for any cadence uniformly, but nothing in the app
actually computes next-occurrence dates yet, and in practice what a user
wants to see and enter is "which day of the month it bills," not a specific
calendar date that happens to recur. This does mean day 31 doesn't exist in
every month --- deliberately not solved here; if/when real date-math lands
(e.g. a "next charge" calculation), it can decide how to clamp/roll that
case then, with real requirements in view instead of a guess now.

=:status= exists so a subscription can become =:cancelled= without being
deleted --- the point is to keep spending history intact rather than lose
it, per the app's original "track and view" goal.

The spec below uses unqualified keys (=s/keys :req-un=/=:opt-un=) because the
app's maps use plain keywords (=:id=, =:name=, ...) rather than namespaced
ones (=:subscription/id=) --- no translation is needed between the maps as
stored and the maps as validated. There is deliberately no foreign-key check
tying =:account-id= to a real entry in =:accounts=; see the notes next to
=events.cljs= for how =::remove-account= keeps that reference from dangling
instead.

=:color= lives on a *category*, not on the subscription. Asking for a color
per subscription would mean choosing one for every single entry; keying it
by category instead means related subscriptions (e.g. everything tagged
"streaming") share a color automatically, and it's chosen once. Categories
stay freeform strings on the subscription itself (no separate id, no
add/remove events) --- =:categories= is just a lookup map from category name
to its metadata, populated lazily as categories get used (see
=events.cljs='s =register-category=), not a managed collection with its own
lifecycle.

   :cost 0

   :custom-interval-days nil
   :billing-day nil               ;; 1-31, day of the month it bills on
   :status :active                ;; #{:active :paused :cancelled}
   :account-id nil                ;; references an entry in :accounts
   :start-date nil
   :category nil                  ;; freeform, lowercased on save; see :categories

   :url nil
   :notes nil
   :created-at nil

(def default-db
  {:subscriptions {}              ;; map of id -> subscription entity

(s/def ::cost number?)

(s/def ::category (s/nilable string?))
(s/def ::auto-renew? boolean?)
(s/def ::url (s/nilable string?))

  (s/keys :req-un [::id ::name ::cost ::frequency ::billing-day ::status]

** NS: subscription-tracker.localstorage
File path: =src/subscription_tracker/localstorage.cljs=

Persistence uses =pr-str=/=cljs.reader/read-string= (edn) rather than JSON.
Edn round-trips ClojureScript data --- keywords, keyword values like
=:monthly= / =:active=, =nil= --- losslessly; JSON would need a translation
layer (stringifying/parsing keywords, deciding on a null convention) for no
real benefit, since nothing outside this app needs to read the stored value.
=cljs.reader/read-string= is used instead of raw =js/eval= specifically
because it is a /data/ reader --- it cannot execute code, so a corrupted or
tampered =localStorage= entry can fail to parse but never do anything worse.

#+BEGIN_SRC clojure :tangle src/subscription_tracker/localstorage.cljs
(ns subscription-tracker.localstorage
  (:require [cljs.reader :as reader]))

(def ls-key
  "localStorage key under which the whole app's data is persisted."
  "subscription-tracker/app-db")

(defn store-data!
  "Writes `data` into localStorage as an edn string."
  [data]
  (.setItem js/localStorage ls-key (pr-str data)))

(defn load-data
  "Reads previously persisted data from localStorage, if any."
  []
  (when-let [stored (.getItem js/localStorage ls-key)]
    (reader/read-string stored)))

** NS: subscription-tracker.events
File path: =src/subscription_tracker/events.cljs=

=check-spec-interceptor= is placed /before/ =->local-store= in
=mutating-interceptors=. Interceptor after-phase functions run in reverse
list order, so that ordering actually means =->local-store='s =:after= runs
first, saving to =localStorage= before the spec check's =:after= gets a
chance to throw. This mirrors the standard re-frame todo-mvc reference
implementation's ordering; a spec violation still throws and surfaces
immediately either way (the bad write to =app-db= already happened by the
time either interceptor runs), so this is flagged rather than "fixed" ---
reordering would diverge from the well-known community pattern for a benefit
that is mostly theoretical at this app's scale.

=::remove-account= cascades --- it clears =:account-id= on any subscription
pointing at the deleted account --- while =::remove-subscription= does not
touch =:accounts=, because the dependency only runs one direction: a
subscription optionally /references/ an account, but an account has no
reference back, so deleting a subscription can't orphan anything. This was a
deliberate UX choice: auto-clearing the reference (with a confirmation
prompt in the UI, once built) beats forcing the user to manually unlink
every subscription first, since an account is incidental context for a
subscription, not something the subscription structurally depends on.

=normalize-category= lower-cases =:category= on the way into =app-db=
(applied in both =::add-subscription= and =::update-subscription=, so it's
enforced regardless of which UI surface submits the data, present or
future) specifically to stop "Streaming" and "streaming" from becoming two
separate categories by accident; the view layer is responsible for
presenting it capitalized. =register-category= then ensures =:categories=
gets an entry (defaulting to no color) for whatever category a subscription
just used, if it doesn't have one already --- this is what keeps
=:categories= populated from ordinary use, with no dedicated "manage
categories" UI required for the map to stay useful. =->local-store= now
persists =:categories= alongside =:subscriptions=/=:accounts=, since it's
real user data (assigned colors) that needs to survive a reload just like
the rest.

#+BEGIN_SRC clojure :tangle src/subscription_tracker/events.cljs
(ns subscription-tracker.events
  (:require
   [clojure.string :as str]
   [re-frame.core :as re-frame]
   [cljs.spec.alpha :as s]
   [subscription-tracker.db :as db]
   [subscription-tracker.localstorage :as localstorage]
   [day8.re-frame.tracing :refer-macros [fn-traced]]))

;; -- Interceptors ------------------------------------------------------------

(defn check-and-throw
  "Throws an exception if `db` doesn't match the given spec."
  [spec db]
  (when-not (s/valid? spec db)
    (throw (ex-info (str "Spec check failed: " (s/explain-str spec db))
                     {:spec spec :db db}))))

(def check-spec-interceptor
  "Validates app-db against ::db/db after every event; throws if invalid."
  (re-frame/after (partial check-and-throw ::db/db)))

(re-frame/reg-cofx
 :local-store
 (fn [cofx _]
   (assoc cofx :local-store (localstorage/load-data))))

(def ->local-store
  "Persists the :subscriptions/:accounts/:categories portion of app-db to
   localStorage after every event."
  (re-frame/after
   (fn [db _]
     (localstorage/store-data! (select-keys db [:subscriptions :accounts :categories])))))

(def mutating-interceptors
  "Applied to every event that makes a significant change to app-db:
   validates the result against spec, then persists it to localStorage."
  [check-spec-interceptor ->local-store])

;; -- Helpers -------------------------------------------------------------

(defn- new-id []
  (str (random-uuid)))

(defn- now-iso []
  (.toISOString (js/Date.)))

(defn- normalize-category
  "Lower-cases :category, if present, so casing variants don't create
   duplicate categories."
  [m]
  (cond-> m (:category m) (update :category str/lower-case)))

(defn- register-category
  "Ensures `category` has an entry in :categories (defaulting to no color
   assigned yet), if it isn't nil and doesn't have one already."
  [db category]
  (if category
    (update db :categories update category #(or % {:color nil}))
    db))

;; -- Events --------------------------------------------------------------

(re-frame/reg-event-fx
 ::initialize-db
 [(re-frame/inject-cofx :local-store)
  check-spec-interceptor
  ->local-store]
 (fn-traced [{:keys [local-store]} _]
            {:db (merge db/default-db local-store)}))

(re-frame/reg-event-db
 ::add-subscription
 mutating-interceptors
 (fn-traced [db [_ subscription]]
            (let [subscription (normalize-category subscription)
                  id (new-id)
                  now (now-iso)
                  entity (merge db/default-subscription subscription
                                 {:id id :created-at now :updated-at now})]
              (-> db
                  (assoc-in [:subscriptions id] entity)
                  (register-category (:category entity))))))

(re-frame/reg-event-db
 ::update-subscription
 mutating-interceptors
 (fn-traced [db [_ id changes]]
            (let [changes (normalize-category changes)]
              (-> db
                  (update-in [:subscriptions id] merge changes {:updated-at (now-iso)})
                  (register-category (:category changes))))))

(re-frame/reg-event-db
 ::add-account
 mutating-interceptors
 (fn-traced [db [_ account]]
            (let [id (new-id)
                  now (now-iso)
                  entity (merge db/default-account account
                                 {:id id :created-at now :updated-at now})]
              (assoc-in db [:accounts id] entity))))

(re-frame/reg-event-db
 ::update-account
 mutating-interceptors
 (fn-traced [db [_ id changes]]
            (update-in db [:accounts id] merge changes {:updated-at (now-iso)})))

(re-frame/reg-event-db
 ::remove-subscription
 mutating-interceptors
 (fn-traced [db [_ id]]
            (update db :subscriptions dissoc id)))

(re-frame/reg-event-db
 ::remove-account
 mutating-interceptors
 (fn-traced [db [_ id]]
            (-> db
                (update :accounts dissoc id)
                (update :subscriptions
                        (fn [subscriptions]
                          (reduce-kv (fn [m sub-id sub]
                                       (assoc m sub-id
                                              (cond-> sub
                                                (= (:account-id sub) id)
                                                (assoc :account-id nil))))
                                     {} subscriptions))))))

** NS: subscription-tracker.subs
File path: =src/subscription_tracker/subs.cljs=

Subscriptions are split into two layers, the standard re-frame convention:
"layer 2" subs (=::subscriptions=, =::accounts=) are thin extractors that
pull the raw map straight out of =app-db= and do nothing else, while
"layer 3" subs (=::subscription-list=, =::subscription=, =::account-list=,
=::account=) build on those via =:<-= input signals rather than reading
=db= directly. Keeping the extractors separate means every derived sub ---
including future ones, e.g. filtered/sorted views in Phase I --- shares the
same memoized =::subscriptions=/=::accounts= reaction instead of each
re-deriving its own path into =app-db=.

#+BEGIN_SRC clojure :tangle src/subscription_tracker/subs.cljs
(ns subscription-tracker.subs
  (:require
   [re-frame.core :as re-frame]))

;; -- Layer 2: extractors -----------------------------------------------------

(re-frame/reg-sub
 ::subscriptions
 (fn [db _]
   (:subscriptions db)))

(re-frame/reg-sub
 ::accounts
 (fn [db _]
   (:accounts db)))

;; -- Layer 3: derived ---------------------------------------------------------

(re-frame/reg-sub
 ::subscription-list
 :<- [::subscriptions]
 (fn [subscriptions _]
   (vals subscriptions)))

(re-frame/reg-sub
 ::subscription
 :<- [::subscriptions]
 (fn [subscriptions [_ id]]
   (get subscriptions id)))

(re-frame/reg-sub
 ::account-list
 :<- [::accounts]
 (fn [accounts _]
   (vals accounts)))

(re-frame/reg-sub
 ::account
 :<- [::accounts]
 (fn [accounts [_ id]]
   (get accounts id)))

** NS: subscription-tracker.views
File path: =src/subscription_tracker/views.cljs=

Phase A renders the subscription list read-only, straight from
=::subs/subscription-list=, to validate the full data flow (app-db -> sub ->
view) before layering in interaction. =subscription-card= and
=subscription-list= are kept as separate functions so the per-card markup
can grow (expand/edit in Phase B/C) without complicating the list's
empty-state/iteration logic, and vice versa.

Phase B adds expand/collapse. Whether a given card is expanded is purely
presentational and never needs to be read by any other component, so it
lives in a local Reagent atom rather than app-db --- per the plan's
local-vs-app-db split, app-db is reserved for state that's actually shared
(like the Phase I sort/filter controls will be). =subscription-card= becomes
a form-2 component (an outer function that creates the =expanded?= atom
once per mounted card, returning an inner render function closing over it)
specifically so that atom survives re-renders of that one card instead of
being recreated every time =app-db= changes. =subscription-details= is kept
as its own function, and does its own =::subs/account= lookup by
=account-id= rather than being passed a resolved account, so it only
subscribes to (and re-renders on) the one account it actually needs, not
the whole =::accounts= map.

Phase D (built ahead of Phase C, see the roadmap note above) adds
=subscription-form=. Its fields are kept as raw strings in local form state
and only coerced (=js/parseFloat=/=js/parseInt=/keyword/blank->nil) at
submit time in =form->subscription=, rather than coercing on every
keystroke --- coercing eagerly means an in-progress edit like clearing a
number field to retype it briefly produces an invalid intermediate value
(e.g. =NaN=), which would either flash a =0= or fight the user's typing.
=blank->nil= specifically matters for the optional fields because an empty
string is still truthy in ClojureScript: =subscription-details='s
=(when url ...)= guards would happily render an empty link/category for a
field the user left blank if it came through as =""= instead of =nil=. The
form doesn't yet accept an existing subscription to pre-fill --- that
parameter gets added when Phase C actually needs it, rather than guessed at
now.

Every field is wrapped in a bare =[:label "Text" [:input ...]]= rather than
paired via explicit =id=/=for= attributes, and styled to stack label-above-
input with CSS alone (=.subscription-form label=). This sidesteps having to
generate unique ids per field --- which would matter once Phase C mounts a
second copy of this form (or a future one) on the same page and two
=id="cost"= inputs would collide --- at the cost of relying on wrapping
instead of an explicit association, which is fine since every field here is
a single input. =:billing-day= is a plain 1-31 number input instead of a
date picker (see the =db.cljs= note on why); =:category= is displayed
capitalized via a =.category-value= CSS class rather than in the data
itself, since the data stays lowercased for de-duplication (see
=events.cljs=). The auto-renew checkbox reads "Will Auto-Renew" rather than
just "Auto-renew," in both the form and the expanded detail view, so it
reads as a description of the subscription's own behavior rather than
something this app is going to go do.

(ns subscription-tracker.views

(defn- format-frequency [{:keys [frequency custom-interval-days]}]
  (if (= frequency :custom)

(defn subscription-details
  "Full field detail shown when a card is expanded."
  [{:keys [billing-day start-date category auto-renew? url account-id notes]}]
  (let [account @(re-frame/subscribe [::subs/account account-id])]
    [:div.subscription-details
     [:div [:span.field-label "Billing day: "] billing-day]
     (when start-date
       [:div [:span.field-label "Started: "] start-date])
     (when category
       [:div [:span.field-label "Category: "] [:span.category-value category]])
     [:div [:span.field-label "Will Auto-Renew: "] (if auto-renew? "Yes" "No")]
     (when account
       [:div [:span.field-label "Account: "]
        (str (:name account) " (••" (:last-digits account) ")")])
     (when url
       [:div [:span.field-label "Manage: "]
        [:a {:href url :target "_blank" :rel "noopener noreferrer"} url]])
     (when (seq notes)
       [:div.subscription-notes notes])]))

(defn subscription-card
  "A single subscription; click the summary row to expand/collapse full detail."
  [_]
  (let [expanded? (r/atom false)]
    (fn [{sub-name :name :keys [cost status] :as subscription}]
      [:div.subscription-card
       [:div.subscription-summary {:on-click #(swap! expanded? not)}
        [:span.subscription-name sub-name]
        [:span.subscription-cost (str "$" cost)]
        [:span.subscription-frequency (format-frequency subscription)]
        [:span.subscription-status (name status)]]
       (when @expanded?
         [subscription-details subscription])])))

(defn subscription-list []
  (let [subscriptions @(re-frame/subscribe [::subs/subscription-list])]
    [:div.subscription-list
     (if (empty? subscriptions)
       [:p.empty-state "No subscriptions yet."]
       (doall
        (for [{:keys [id] :as subscription} subscriptions]
          ^{:key id} [subscription-card subscription])))]))

(def ^:private empty-subscription-form
  {:name "" :cost "" :frequency :monthly :custom-interval-days ""
   :billing-day "" :start-date "" :category "" :account-id ""
   :auto-renew? true :url "" :notes ""})

(defn- blank->nil [s]
  (when (seq s) s))

(defn- form->subscription
  "Coerces raw string form state into the shape ::events/add-subscription expects."
  [{:keys [name cost frequency custom-interval-days billing-day start-date
           category account-id auto-renew? url notes]}]
  {:name name
   :cost (js/parseFloat cost)
   :frequency frequency
   :custom-interval-days (when (= frequency :custom) (js/parseInt custom-interval-days))
   :billing-day (js/parseInt billing-day)
   :start-date (blank->nil start-date)
   :category (blank->nil category)
   :account-id (blank->nil account-id)
   :auto-renew? auto-renew?
   :url (blank->nil url)
   :notes (blank->nil notes)})

(defn subscription-form
  "Inline create form for a new subscription."
  [{:keys [on-success]}]
  (let [form (r/atom empty-subscription-form)]
    (fn [_]
      (let [{form-name :name :keys [cost frequency custom-interval-days
                                     billing-day start-date category
                                     account-id auto-renew? url notes]} @form
            accounts @(re-frame/subscribe [::subs/account-list])]
        [:form.subscription-form
         {:on-submit (fn [e]
                       (.preventDefault e)
                       (re-frame/dispatch [::events/add-subscription (form->subscription @form)])
                       (reset! form empty-subscription-form)
                       (when on-success (on-success)))}
         [:label "Name"
          [:input {:type "text" :required true
                   :value form-name
                   :on-change #(swap! form assoc :name (.. % -target -value))}]]
         [:label "Cost"
          [:input {:type "number" :step "0.01" :required true
                   :value cost
                   :on-change #(swap! form assoc :cost (.. % -target -value))}]]
         [:label "Frequency"
          [:select {:value (name frequency)
                    :on-change #(swap! form assoc :frequency (keyword (.. % -target -value)))}
           (doall
            (for [f [:weekly :monthly :quarterly :yearly :custom]]
              ^{:key f} [:option {:value (name f)} (name f)]))]]
         (when (= frequency :custom)
           [:label "Interval (days)"
            [:input {:type "number"
                     :value custom-interval-days
                     :on-change #(swap! form assoc :custom-interval-days (.. % -target -value))}]])
         [:label "Billing Day (1-31)"
          [:input {:type "number" :min "1" :max "31" :step "1" :required true
                   :value billing-day
                   :on-change #(swap! form assoc :billing-day (.. % -target -value))}]]
         [:label "Start Date"
          [:input {:type "date"
                   :value start-date
                   :on-change #(swap! form assoc :start-date (.. % -target -value))}]]
         [:label "Category"
          [:input {:type "text"
                   :value category
                   :on-change #(swap! form assoc :category (.. % -target -value))}]]
         [:label "Account"
          [:select {:value account-id
                    :on-change #(swap! form assoc :account-id (.. % -target -value))}
           [:option {:value ""} "No account"]
           (doall
            (for [{:keys [id name last-digits]} accounts]
              ^{:key id} [:option {:value id} (str name " (••" last-digits ")")]))]]
         [:label.checkbox-label
          [:input {:type "checkbox" :checked auto-renew?
                   :on-change #(swap! form assoc :auto-renew? (.. % -target -checked))}]
          " Will Auto-Renew"]
         [:label "Management URL"
          [:input {:type "text"
                   :value url
                   :on-change #(swap! form assoc :url (.. % -target -value))}]]
         [:label "Notes"
          [:textarea {:value notes
                      :on-change #(swap! form assoc :notes (.. % -target -value))}]]
         [:button {:type "submit"} "Add subscription"]]))))

(defn subscriptions-panel []
  (let [show-form? (r/atom false)]
    (fn []
      [:div.subscriptions-panel
       [:div.panel-header
        [:h2 "Subscriptions"]
        [:button {:type "button" :on-click #(swap! show-form? not)}
         (if @show-form? "Cancel" "+ Add subscription")]]
       (when @show-form?
         [subscription-form {:on-success #(reset! show-form? false)}])
       [subscription-list]])))

(defn main-panel []
  [:div
   [:h1 "Subscription Tracker"]
   [subscriptions-panel]])
